# Payment methods, transfer fees and Overview currency

The shared method form uses method pills and conditional Card type / Account type choices. New bank accounts default to Savings account, with Checking account and Other bank account available. Existing generic/custom types survive an unchanged edit. Credit-card funding type remains immutable. The redundant text input is removed.

Transfer amount is the amount entered by the user. A positive optional fee is either added on top or deducted from that amount, always paid by the source. Preview the source deduction and destination receipt. Persist `amount` as the **received principal**, `fee_amount` as a nonnegative decimal, and `fee_mode` as `added` / `deducted`. Reconstruct deducted-mode input as principal plus fee when editing. Reject invalid money, combined overflow and zero/nonpositive received principal.

Migration 0032 links exactly one owned expense to each positive fee. The principal remains a balanced internal transfer; the expense alone reduces combined balances and appears in expenses, budgets, reports and exact exports. Reuse an owned Fees category or create one when needed. Atomic transfer RPCs manage the pair. A private transaction-scoped writer capability, direct-write guards and deferred consistency constraints protect it from ordinary expense/item/bill APIs and older clients. Reset and actual Auth cascades remain supported. Fee assignments and dates follow the transfer source, preserving baseline and future-date behavior. Fee-only increases and edits replacing previous deductions use the existing owner financial lock and include the entire source cost. Credit sources continue to track debt without an invented available-credit limit.

The transfer JSON save accepts `payload_version: 2`, optional `feeAmount` decimal string and `feeMode`. Omitted metadata preserves existing fees; explicit zero removes the expense. Snapshot money remains decimal strings and advertises `transferFeeVersion: 1`. Report transfer money remains exact integer-cent strings. The client disables positive-fee entry until the owner/timezone-scoped snapshot advertises support and validates mutation responses. Supported clients use the new `save_payment_transfer_with_fee` RPC identity, which delegates to the atomic writer; an older server rejects it before any principal-only write, even with stale cached capability. Fee-free unsupported clients keep the legacy RPC. Linked fee review opens its transfer, with no separate expense edit/delete. Fee expenses are excluded from bill settlement choices. Both histories disclose fees; transfer deletion discloses removal of the fee expense. All affected aggregate, transaction, category, method and report caches refresh together.

Overview's Income, Expenses and Net cash flow use `useMoneyCents` with integer-cent arithmetic. Expo's enabled React Compiler previously memoized plain `formatMoney(amount)` calls by amount alone, hiding their implicit preference-store dependency. A compiler-enabled test compiles the actual Overview and money hook and verifies USD-to-PHP updates with unchanged totals/owner. Related payment-method balances, history and corrections also subscribe explicitly to currency.
