# Confirmed bills and review fixes

The user approved critique findings 1, 2, 4 and 5 plus the three screen improvements. Refunds and other optional additions are outside this change. Builds, deployments and update publication remain on hold.

Schedules generate pending occurrences and advance the next scheduled date without creating expenses. Explicit recording or linking establishes payment. Existing recorded history stays unchanged. Current-month guidance includes older unpaid obligations; they remain visible as overdue and reserved until recorded, linked, skipped or replaced. Historical month views retain their own date ranges.

The compact payment form keeps the saved amount and due date read-only. Payment date defaults to the current financial date and has a small optional edit control. The server accepts an actual payment date on or before today while checking the original due date and amount for stale drafts. Five-argument legacy callers remain compatible through the optional sixth argument. Legacy retries keep a committed payment date. Existing exact-payment retries, credit debt tracking, funds guards and source/receipt ownership remain.

New bills receive a stable creation UUID per owner/form visit. A private owner-scoped creation receipt stores the exact original payload and rule association. The owner financial lock serializes creates. An exact retry returns the existing rule, including subsequent edits/archive, without overwriting or restoring it. Conflicting payloads and foreign requests fail. The internal schedule writer is no longer directly executable by clients. Receipt rows cascade with their bill on account/finance reset.

Transaction deletion and expense replacement require a confirmation that names the saved amount/date and removal of any receipts. Linked deletion skips the bill; replacement restores a pending obligation. Cancel preserves the editor draft. Success closes the native modal before navigation, since tab routes remain mounted. Replacement sends the original transaction ID and rejects a newer payment from another device; repeating an already completed replacement is safe.

Overview puts the month below the heading and groups multiple overages into an expandable count. Individual detail/dismiss actions and owner/month isolation stay. Manual transaction entry puts Type and Amount first, uses a compact searchable category sheet, and places optional notes/attachments later. Required receipt decisions and counted-row totals stay. Settings keeps the underlined tabs and hidden scrollbars, adds a scroll/return arrow, and reveals selected tabs. Category reports label Remaining/Over by and expose Spent/Budget; names can grow and supporting type is 12px. Net cash flow is consistent in Overview and reports.
